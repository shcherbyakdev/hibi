# Goals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Goals you work toward with daily tasks, and a GitHub-style grid that shows the days you actually moved each goal forward.

**Architecture:** A new synced `goals` table, plus a nullable `items.goal_id`. A goal's progress is **derived, never stored**: each day's cell counts the goal's tasks whose `done_at` falls on that local date. Everything runs on the existing local-first sync (Dexie + outbox + Supabase). The pure date and count math lives in `features/goals/model.ts` and is unit-tested.

**Tech Stack:** Next 16 App Router, React 19, Drizzle + Supabase (RLS, Realtime), Dexie, Tailwind v4, Vitest.

**Spec:** the "Design" section below. The user skipped brainstorming, so these are my calls. Change any of them before execution starts.

## Design

- **Goal** = name, notes, colour (reuses the board tone keys from `features/boards/tone.ts`), `weekly_target` (how many days a week you want to work on it, 1–7, default 5), `sort_key`. Delete is soft, like every synced table.
- **Linking:** a task belongs to at most one goal (`items.goal_id`, FK `on delete set null`). There are three ways to link one:
  1. Quick add on a goal's page creates a task **planned for today** that is already linked. This is the main loop: look at the goal, then add today's step.
  2. A "Goal" select in the task details sheet.
  3. Tasks keep everything else they have (planner, board, timer).
- **Progress:**
  - **Day cell** = the number of that goal's tasks marked done on that local day. It has 5 levels like GitHub (0, 1, 2, 3, 4+), drawn in the goal's colour at rising opacity.
  - **Streak** = consecutive days with ≥1 done, counted back from today. An empty today doesn't break it; the count then starts from yesterday.
  - **This week** = days in the current week (honouring the week-start setting) with ≥1 done, out of `weekly_target`.
- **Screens:**
  - `/goals`: one card per goal (name, about the last 20 weeks of grid, streak, "3/5 this week"), plus inline "New goal".
  - `/goals/[id]`: a 53-week grid, rename, colour, weekly target, notes, quick add for today, open tasks, and recently done tasks.
  - The sidebar and ⌘K get a "Goals" entry through `nav.ts`.
  - The task sheet gets a Goal field. Rows linked to a goal show a small dot in the goal's colour.
- **Deleting a goal** unlinks its tasks (`goal_id = null`), as one batch of local mutations. The tasks themselves stay.
- **Not now (YAGNI):** recurring habits (auto-create a task every day; `PLAN.md` already lists recurrence as "later"), numeric targets ("read 300 pages"), sub-goals, AI-suggested tasks, an archive state, and a combined all-goals grid. Add them once real use asks for them.

## Global Constraints

- Follow `AGENTS.md`: read `node_modules/next/dist/docs/` before touching routing or pages. Next 16 conventions differ from training data. Copy route and page shapes from `src/app/(app)/boards/[id]/`.
- Dates are local calendar dates: always `toISODate(new Date(...))` from `features/planner/periods.ts`, never `toISOString().slice(0,10)`.
- No new dependencies.
- The new table gets the full sync treatment from `0003_time_entries_rls.sql`: owner FK, `sync_stamp` trigger, revoke from anon, grant CRUD to authenticated, owner RLS policy, Realtime publication.
- Push order is FK order: `goals` goes before `items` in `SYNCED_TABLES`.
- Keep the visual language from `docs/PLAN.md` §6/7: square corners, uppercase mono labels, tones only from `BOARD_TONES`.
- `npm run verify` must pass at every commit.

## Review Focus

1. **A task finished at 23:30 local time east of UTC** must land on that day's cell, not the day before. This is pinned by a model test that uses `TZ`.
2. **Un-done or dropped tasks** must leave the grid. `setStatus` already nulls `done_at`; the test checks that count only reads `done_at` and `deleted_at`.
3. **Soft-deleted tasks** must not count. This is pinned in the `dayCounts` test.
4. **Today still empty** must not zero the streak. This is pinned in the `streak` test.
5. **Week start = Sunday:** grid rows and "this week" must both follow the setting. This is pinned in the `gridWeeks` and `weekCount` tests.

### Task 3: Progress model

**Files:**
- Create: `src/features/goals/model.ts`
- Test: `src/features/goals/model.test.ts`

**Interfaces:**
- Consumes: `toISODate`, `addDays`, `startOfWeek` from `features/planner/periods.ts`.
- Produces:
  - `type DayCounts = Map<string, number>`. The key is a local `YYYY-MM-DD` date.
  - `dayCounts(items: Pick<Item, "goal_id" | "done_at" | "deleted_at">[], goalId: string): DayCounts`
  - `level(n: number): 0 | 1 | 2 | 3 | 4`
  - `gridWeeks(today: string, weeks: number, weekStart: 0 | 1): string[][]` returns `weeks` columns of 7 dates. The first row is `weekStart`, and the last column contains `today`. Future dates are included; the UI dims them.
  - `streak(counts: DayCounts, today: string): number`
  - `weekCount(counts: DayCounts, today: string, weekStart: 0 | 1): number`

- [ ] **Step 1: Write the failing tests.**

```ts
const done = (at: string, over = {}) => ({ goal_id: "g", done_at: at, deleted_at: null, ...over });

it("counts done tasks per local day, skipping other goals, open and deleted tasks", () => {
  const c = dayCounts([done("2026-11-12T08:00:00"), done("2026-11-12T18:00:00"), done("2026-11-12T09:00:00", { goal_id: "x" }),
    done("2026-11-12T10:00:00", { deleted_at: "2026-11-13T00:00:00Z" }), { goal_id: "g", done_at: null, deleted_at: null }], "g");
  expect([...c]).toEqual([["2026-11-12", 2]]);
});
it("uses the local day east of UTC", () => { /* run under TZ=Asia/Tokyo, pattern from periods.test.ts */
  expect([...dayCounts([done("2026-11-12T15:30:00Z")], "g").keys()]).toEqual(["2026-11-13"]);
});
it("levels like GitHub", () => expect([0, 1, 2, 3, 4, 9].map(level)).toEqual([0, 1, 2, 3, 4, 4]));
it("grid ends on today's week and starts rows on the week-start day", () => {
  const g = gridWeeks("2026-11-14", 2, 1); // Saturday, Monday weeks
  expect(g).toEqual([["2026-11-02", "2026-11-03", "2026-11-04", "2026-11-05", "2026-11-06", "2026-11-07", "2026-11-08"],
                     ["2026-11-09", "2026-11-10", "2026-11-11", "2026-11-12", "2026-11-13", "2026-11-14", "2026-11-15"]]);
  expect(gridWeeks("2026-11-14", 1, 0)[0][0]).toBe("2026-11-08");
});
it("streak survives an empty today and breaks on a gap", () => {
  const c = new Map([["2026-11-13", 1], ["2026-11-12", 2], ["2026-11-10", 1]]);
  expect(streak(c, "2026-11-14")).toBe(2);
  expect(streak(new Map([...c, ["2026-11-14", 1]]), "2026-11-14")).toBe(3);
  expect(streak(new Map(), "2026-11-14")).toBe(0);
});
it("weekCount counts days, not tasks, in the current week", () => {
  const c = new Map([["2026-11-09", 3], ["2026-11-14", 1], ["2026-11-08", 1]]);
  expect(weekCount(c, "2026-11-14", 1)).toBe(2);
  expect(weekCount(c, "2026-11-14", 0)).toBe(3); // Sunday week Nov 8–14 holds all three
});
```
